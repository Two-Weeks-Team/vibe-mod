# 06 — Reliability / Failure-Mode Analysis (FMEA)

Scope: `src/server/index.ts`, `src/server/fact-bag.ts`, `src/server/executor.ts`, `src/server/evaluator.ts`, `src/shared/rule-schema.ts`, `devvit.json`, `docs/devvit-reference.md`. Read-only analysis — no code changed.

## 1. Summary

vibe-mod is reasonably defensive in the "happy-ish path" — fact-bag swallows all Reddit errors, OpenAI failures degrade to a toast, dedupe guards trigger retries, rate-limit/circuit-breaker/kill-switch all short-circuit `executeActions`, and shadow/dry-run modes default ON. But there are **three structural reliability holes** that the prior audits did not close:

1. **The `zRange ... {by:'score'}` 1000-row server cap (`docs/devvit-reference.md` "Sorted sets" table) breaks both the circuit breaker (`index.ts:737`) and audit retention (`index.ts:609`).** The breaker silently fails for any `maxActionsPerHour > 1000`; retention orphans `:audit:<id>` hashes when >1000 entries age out in one day → unbounded Redis growth → quota gating → *writes blocked app-wide*.
2. **A malformed/legacy rule bundle in Redis crashes every trigger.** `RuleBundle.parse(JSON.parse(...))` at `index.ts:498` / `:539` is not wrapped in try/catch, and `onAppUpgrade` (`index.ts:584-587`) is a no-op — a schema change ships, the persisted bundle no longer validates, and `onPostSubmit`/`onCommentSubmit` 500 for every submission until a human re-compiles.
3. **A trigger storm (brigade) is uncapped and fails *unsafe*.** Each `onPostSubmit` does ~3 Reddit API calls via the fact bag + N×(several calls) per matching rule, all serial, with no time budget. Under Reddit rate-limiting, `getUserByUsername` throws → `SAFE_AUTHOR_DEFAULTS` returns `accountAgeHours: 0`, `hasVerifiedEmail: false`, `totalKarma: 0` (`fact-bag.ts:176-183`) — i.e. every author looks like a brand-new throwaway, so "new account"/"low karma" rules match *everything* and mass-action legitimate posts. The 30s execution cap is also exceeded long before 50 rules × 5 actions complete.

Everything else below is lower severity but worth fixing.

## 3. Prioritized Hardening List

1. **Replace the audit-ZSet-scan circuit breaker with a TTL'd per-hour counter** incremented inside `executeActions` on `outcome:'applied'`. (Fixes #1; also de-risks #3.)
2. **Make `audit-retention` paginate hash deletion (or daisy-chain), and add a Redis-usage alarm.** (Fixes #2 → the worst blast radius — app-wide write failure.)
3. **Wrap every `RuleBundle.parse` on the trigger/Dashboard path in try/catch; fail to "no active rules" + modmail, not 500. Quarantine the broken bundle.** (Fixes #4.)
4. **Implement a real `onAppUpgrade` schema migration** (versioned transform chain). (Fixes #5; prevents the most likely cause of #4.)
5. **Make the trigger path fail-safe under API errors:** flag "degraded" facts when a Reddit call errored, and have the evaluator refuse to act on rules that depend on degraded facts. Add a per-minute submission spike detector that auto-opens the circuit. (Fixes the dangerous half of #3.)
6. **Add a time budget to `executeActions`/the trigger loop** (bail + re-queue before ~25s) and make dedupe per-(thing,rule,action) so retries resume. (Fixes #7.)
7. **Write an "intent" record before `applyAction`** so a post-action audit-write failure still leaves an undo-able trail. (Fixes #6.)
8. **Add `AbortController` timeout + one retry to the OpenAI `fetch`.** (Fixes #8.)
9. **Add the `author.id === appAccountId` self-event guard to all trigger handlers.** (Fixes #10; matches `docs:777`.)
10. **Make `shadow-promote-check`'s bundle rewrite use `watch/multi/exec` with retry.** (Fixes #11.)
11. **Retry-loop the `watch/multi/exec` blocks in `isDuplicateTrigger` and `trySetIfNotExists`.** (Fixes #12.)
12. Add a unit test asserting `dry-run-replay` never references `executeActions`; lower `DRY_RUN_SAMPLE` or add a time budget. (Hardens #14.)

## 4. Do NOW vs LATER

**Do NOW (correctness/safety, small surface):**
- #4 try/catch around `RuleBundle.parse` on trigger + Dashboard paths — one-line-per-call, prevents total outage.
- #1 circuit-breaker counter — the comment claims this is fixed but it is not for `maxActionsPerHour > 1000`, and it counts the wrong outcomes.
- #2 audit-retention pagination/daisy-chain — silent unbounded growth is the highest-blast-radius issue.
- #10 self-event guard — trivial, and `docs:777` explicitly calls for it.
- #8 OpenAI fetch timeout — trivial, prevents form-handler hangs.

**LATER (needs design/testing):**
- #5 `onAppUpgrade` migration framework (needs schema-version conventions).
- #3 degraded-fact propagation + spike-based auto-circuit (touches evaluator, fact-bag, schema).
- #6/#7 per-trigger time budget, per-action idempotency, pre-action intent records (touches executor + dedupe semantics).
- #11/#12 atomic-rewrite + retry loops (correctness under rare races).
- #17 real `reports.distinctReporters` (or remove the fact).
