0. TL;DR (한 줄 결론)

FlairGuard는 "mod가 removal flair를 다는 순간 자동 처리" 한 가지 시나리오에 집중한 좁고 깔끔한 앱이다. vibe-mod는 자연어 → 결정적 JSON rule 컴파일러로 훨씬 넓은 표현력을 제공한다. 가져올 1순위는 (1) onPostFlairUpdate 트리거 추가 (vibe-mod 자연어로 "When a mod applies 'Spam' flair, remove and lock and notify the author" 표현 가능)와 (2) Welcome onboarding modmail (first-install 시 모드팀에 사용법 발송 — 발견성 ↑).

핵심 동작 (인용)

FlairGuard is a Reddit mod tool that automatically enforces moderation actions the moment a moderator applies a removal flair to a post. It eliminates the most repetitive part of moderating — typing the same removal reason over and over.

3. 배울 점 / 차용 후보

3.1 HIGH onPostFlairUpdate 트리거 추가

vibe-mod 트리거 enum에 한 줄 추가하면 자연어로 flair-driven 룰을 표현 가능:

user input"When a mod applies the 'Spam' flair to a post, remove it,
 lock the thread, and notify the author via modmail."

FlairGuard처럼 mod가 매 flair마다 GUI에서 설정할 필요가 없다. 같은 결과를 자연어 한 문장으로.

  • 변경 위치: src/shared/rule-schema.ts RULE_TRIGGERS enum + src/server/routes/triggers.ts 새 핸들러 + src/shared/system-prompt.ts trigger 설명에 onPostFlairUpdate 안내 1줄
  • 예상 LOC: ~80 (route handler + 1 fact path "post.appliedFlairText" + tests)
  • 위험: Devvit가 onPostFlairUpdate trigger payload 형태 다름 → 새 fact 추출 코드 필요

3.2 HIGH Welcome onboarding modmail

FlairGuard는 first install 시 모드팀 전체에 modmail을 보낸다. vibe-mod의 dashboard onboarding card는 사용자가 menu에 들어가야만 보인다 → push vs pull 차이.

  • 변경 위치: src/server/routes/scheduler.ts seed-on-install 핸들러 + Redis 멱등 flag (${sub}:onboarding:welcomemail)
  • 내용: vibe-mod 3-menu 안내 + Compose 첫 룰 예시 + safety story (shadow 24h, undo)
  • 위험: 발송 실패 시 retry 정책 → 일단 best-effort 1회

3.3 MEDIUM README/Devpost에 vs Automations / vs AutoMod 비교 표 강화

FlairGuard처럼 명시적 비교 매트릭스가 강력하다. vibe-mod의 Devpost는 이미 partial이지만 표 형태로 압축하면 심사자에게 더 빨리 전달.

3.4 MEDIUM Dashboard recent actions 5 → 20

FlairGuard "Last 50 actions in mod menu". vibe-mod는 5건만 미리보기 + redis 30d 전체 보관. 모드 즉시 파악도를 위해 dashboard preview 캡 ↑.

  • 변경 위치: src/server/routes/dashboard.ts recent.slice(0, 5) → 20
  • 비용: 0 (이미 fetch 됨, slice만)

3.5 INVEST Devvit webview UI

FlairGuard "vanilla HTML/CSS/JS settings dashboard" 표현은 Devvit Web Views 사용 추정. vibe-mod의 단일 줄 textarea 한계를 webview로 우회 가능.

주의: 큰 작업 + form 시스템과 일관성 깨짐. publish 후 polish로.

3.6 LOW Markdown 지원 명시 (docs)

vibe-mod의 modqueue note / ban reason / report reason은 Reddit이 자동 Markdown 렌더링. README에 명시만 추가하면 신기능 0 + 사용성 ↑.

4. 차별화 포인트 (Devpost 강조용)

  • LLM-as-compiler 패턴 — FlairGuard가 매 flair 별 GUI 설정 필요한 자리에서, vibe-mod는 같은 결과를 자연어 한 문장으로 표현한다. 룰 작성 마찰 ↓.
  • Shadow mode 24h + dry-run preview — FlairGuard는 즉시 live (취소는 모드 수동). vibe-mod는 활성화 전 dry-run으로 "would have matched X/Y" 확인 + 24h shadow 동안 로그만 남긴다.
  • 30-day rollback on every action — FlairGuard는 dedup만, undo 없음. vibe-mod는 모든 live action에 1-click undo (post/comment 메뉴).
  • 표현력 — 4 트리거 × 28 facts × 9 operators × all/any/not boolean tree → flair-only 1차원 매칭의 100배+ 표현 공간.
  • Action whitelist + guarded checkbox — ban/mute/permaban은 mod의 명시적 토글 + 서버측 거부 게이트 + 24h shadow + 30d undo. 안전한 위험 액션.
스토리: "FlairGuard 같은 1-flair 워크플로우도 vibe-mod 자연어 한 줄로 표현 + shadow/dry-run/undo로 더 안전하게."
